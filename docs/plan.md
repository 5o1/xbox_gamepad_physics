## 2. 下一阶段：交付一份可供下游使用的资产

按顺序完成以下三步，完成后下游实验就可以开始使用这份资产。

- [x] 提交阶段 B 的代码和文档，以及第 2 版阶段报告。

### 2.2 灵巧手接触与操控验证

- [ ] 确定下游的使用方式：手柄固定在桌上、只操作控件，还是需要把手柄拿起来。这决定了验证的重点。
- [ ] 确定所用的灵巧手模型及其碰撞体质量。现有的 G20 模型碰撞体比较粗，掌部凸包外胀的 95 分位数达 5.24 mm（报告第 7.3 节）。
- [ ] 每个控件都能被手指按下或推动，并输出正确的信号。
- [ ] 按某个控件时，相邻控件不被误触；按下时的阻挡量符合预期。孔口外胀约 1–1.5 mm，这一点要专门检查（报告第 8.7 节）。
- [ ] 如果下游需要拿起手柄：采用包拢型抓取（手掌贴住一面，手指绕过侧面），并按文献的方法验证，例如依次在 6 个方向施加重力（报告第 3.3 节）。
- [ ] CoACD 和 SDF 两种变体各验证一遍；SDF 变体需要 SAPIEN 3.0.3。

### 2.3 发布有版本号的资源

- [ ] 正式发布一次 GitHub Release 资源包，下游按版本号引用。
- [ ] 决定 RoboTwin fork 中的 SAPIEN 3.0.3 升级（提交 `57d8e95`）是否 push。只有使用 SDF 变体时才需要它。

### 下游使用时的约定

- 关节名、通道名和 32 维状态格式保持不变。参数或碰撞体以后的调整，不应要求下游改代码。
- 现有参数都是估计值，`references/` 记录了大多数参数的取值范围。下游训练时建议在这些范围内做随机化，以减少实测参数替换后需要重训的可能。

## 4. 验收边界

以下几类结论要分开表述，不能互相替代：

- “能加载、能步进、信号能往返”只说明软件链路可用；
- 负责人看过渲染并确认，说明外观可接受；
- 接触与动力学验证需要专门的实验；
- 实物标定需要真手柄。

自动测试和代理执行的结果，都不等于负责人的验收。
