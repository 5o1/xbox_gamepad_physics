# CoACD 碰撞体优化（下一阶段）

记录于 2026-10-11，2026-10-12 更新。状态：文献调研已完成，方案和待决事项已整理。负责人决定（2026-10-12）：默认碰撞体改为 SDF，CoACD 凸体优化作为下一阶段的方向，并与孔口外胀、Guide 开口被凸块盖住的问题合并处理，见 `docs/plan.md` 第 3 节。

## 1. 问题

- 阶段 B 接入的 CoACD 碰撞体共 236 个凸块。
- 负责人看了“只画凸块”的渲染图后认为块数偏多。最明显的是摇杆：形状规则，却被切成许多细碎的凸块。
- 负责人定下的目标：**精度不降，块数最少**。
- 负责人希望最终形成两个工具：
  - **自动分析工具**：找出哪些部分可以拼成一个凸块；
  - **自动组合凸块工具**：把自动分析的结果和人工选定的分组结合起来，自动拼出凸块。
- 负责人允许简化碰撞底模中的装饰细节。

## 2. 调研结论

完整报告（含原文出处、源码行号、检索记录）在本地 `build/experiments/collision_opt_lit_20261011/REPORT.md`，由执行代理 Codex 完成，主助手抽查了 6 条引文。要点如下：

1. **调现有工具的参数，做不到“精度不降”。**
   - CoACD 1.0.14 一旦设置块数上限（`max_convex_hull`），合并时会突破凹度阈值，见源码 `src/process.cpp` 中的 `MergeConvexHulls`。
   - V-HACD v4.1.0 和 CGAL 6.2 的近似凸分解，都是按体积代价合并到目标块数。
   - 三者都没有以毫米外胀为硬约束。
2. **“全局最少块数”无法承诺。**
   - 精确的最少凸划分是 NP 难问题（Chazelle 1984）。
   - 我们的问题允许凸块重叠、允许有限外胀，相关文献中没有找到最优性的理论结果。
   - 能做到的是：在一个给定的候选集合里求最少块数，并给出上下界作为证据。
3. **可借鉴的工作：**
   - **按区域设定容差**：Empart（Vu 等，arXiv:2509.22847）。它当前的源码关闭了跨区域合并，原因是合并会违反区域约束。
   - **保护指定空间**：Navigation-Driven ACD（Andrews，SIGGRAPH 2024）规定凸块不得侵入指定空间，可以用来保护孔口和帽沿下方的空隙。
4. **装饰细节可以先简化，但误差要相对原碰撞底模分开计量。**
   - 精确的形态学闭运算可以填平浅槽，并且始终包住原形；
   - 开运算和 QEM 减面不保证包住原形；
   - 防滑纹删到什么程度会影响接触功能，需要负责人认定。
5. **规则图元替代不了整根摇杆。**
   - 凸图元分解（Knodt & Gao，arXiv:2602.07369）只保证凸体覆盖原表面，不保证覆盖实体内部；它的速度结论来自 Rapier 引擎，而且是用更多、更便宜的图元换来的，块数并未减少。
   - SAPIEN 3.0.3 中的圆柱实际上是 32 边的凸网格。

## 3. 方案计划（2026-10-12）

负责人要求这一阶段同时解决两个问题：**孔口被凸块填平**和**块数太多**。两者用同一套约束和检查工具，先修孔口，再合并。三个调研方案的关系：调研方案 1（贪心合并）是主体，方案 2（整数规划）和方案 3（简化装饰细节）作为可选项放在 P4。

### 3.1 两个问题

- **孔口被填平**：CoACD 以凹度作为阈值（外壳用 0.03），开口浅、口径小时，凸块可以跨过或填平开口。Guide 上方的外壳凸块（`controller_body` 形状 59）就是这样，孔口处普遍还有约 1–1.5 mm 的外胀（阶段报告第 8.7 节）。CoACD 现有的参数里没有“这块空间不许占”这类约束。
- **块数太多**：现有 236 块，设置块数上限又会突破精度（见第 2 节）。摇杆防滑环一项就有 20 块左右。

### 3.2 共同约束（负责人已确认）

每个候选碰撞体都要同时满足：

| 约束 | 内容 |
|---|---|
| 精度 | 以原碰撞底模为基准，各组件外胀的最大值和 95 分位数都不超过现状（外壳为 2.42 mm 和 1.15 mm） |
| 不内缩 | 碰撞体包住原底模；用采样检查，结论写成“采样通过”，不写成连续误差已证明 |
| 保护空间 | 凸块不得侵入（借鉴 Navigation-Driven ACD） |
| 合并范围 | 不同运动连杆之间不合并；同一连杆内的不同壳（例如外壳和前板、摇杆主体和防滑环）可以作为合并候选，由上面的约束筛选 |
| PhysX 限制 | 每块不超过 255 个顶点，并量化 cooking 时简化带来的误差 |

**优化目标**：在上述硬约束下块数最少。PhysX 的实际耗时只报告，不作为目标。

**保护空间**由运动契约自动生成，不需要人工标注：

- **控件的运动扫掠体**：每个控件的碰撞底模在关节全行程内扫过的体积，外壳凸块不能挡住控件运动；
- **接近通道**：从控件顶面沿按压方向向外伸出 3 mm 的柱体，截面取控件顶面向内缩 0.3 mm，保证手指或小球能碰到控件顶面；
- **人工补充**：摇杆帽沿下方的空隙要保护。肩键和扳机边缘等其他空隙，在 P1 的体检结果出来后再定。

### 3.3 对称性（对称分析的结论）

2026-10-12 的对称分析（`build/experiments/symmetry_analysis_20261012/REPORT.md`）表明：

- 对称面就是 x = 0，由精确镜像顶点对确定（外壳约 26% 的顶点有误差小于 0.001 mm 的镜像点）；
- 外壳不能整体镜像：镜像残差小于 0.1、0.5、1 mm 的面积分别占 56.1%、78.2%、90.1%。不对称的地方除了控件开口，还有两侧侧壳和握柄的大片区域（最大约 5.5 mm），外观网格上也一样；
- 左右扳机完全镜像（0.00005 mm 以内），左右肩键除一个边缘顶点差 1.06 mm 外基本镜像，左右摇杆尺寸不同；
- 现有 CoACD 结果左右不对称：扳机的底模完全镜像，分解结果却是左 10 块、右 9 块。

据此：扳机分解一次后镜像到另一侧；肩键大部分镜像、不一致的边缘单独处理；外壳只在对称区域加镜像约束，不对称区域及其过渡带单独分解；摇杆左右分别处理。

### 3.4 分阶段计划（由 Codex 执行，每个阶段结束后由主助手审查）

| 阶段 | 内容 | 交付与门槛 |
|---|---|---|
| P1 分析工具 | 计算相对原底模的误差场；生成保护空间并检查侵入；对现有 236 块逐一体检；接入对称分析的分区 | 侵入保护空间的凸块清单（应包含 `controller_body` 形状 59）、每个开口的外胀量、热点图 |
| P2 修孔口 | 对侵入的凸块，把它覆盖的那部分底模沿保护空间边界切开，重新求凸包，直到不再侵入。只改出问题的凸块 | 侵入为 0，精度不比现状差；用 CoACD 跑小球端到端按压，Guide 必须通过，并检查摇杆偏轴 |
| P3 合并工具 | 以 P2 的结果为最小单元，生成同一连杆内的合并候选，用 3.2 节的约束筛选，再贪心组合；支持人工指定锁定、必须合并、禁止合并 | 新的碰撞体、误差表、每个候选被拒绝的理由；不自动替换正式资产 |
| P4 可选 | ① 按 3.3 节利用对称性；② 对候选集合做整数规划，求候选集合内的最少块数和上下界（需要新增求解器依赖，待批准）；③ 简化防滑环这类装饰细节（简化到什么程度由负责人认定） | 视 P3 的效果决定 |
| P5 验证 | 用 CoACD 跑小球端到端按压 26 项、掉落测试和物理耗时，与 SDF 并排比较；出凸块叠加图给负责人验收 | 负责人验收后，再决定是否替换正式的 CoACD 资产。默认碰撞体仍是 SDF |

## 4. 负责人的决定与尚未决定的事项

已决定（2026-10-12）：

1. **精度基准**：原碰撞底模；各组件外胀的最大值和 95 分位数都不增加，保护空间的侵入为 0。
2. **保护空间**：控件运动扫掠体，加上 3 mm、截面内缩 0.3 mm 的接近通道，以及摇杆帽沿下方的空隙。
3. **合并范围**：同一连杆内的不同壳可以作为合并候选；不同运动连杆之间不合并。
4. **优化目标**：在硬约束下块数最少。

尚未决定：

1. 防滑纹可以删到多大尺度；帽顶凹坑算不算接触功能区（P4 ③ 之前决定）。
2. 人工分组是硬约束，还是只作为优先候选；是否需要“候选集内最优”的证据（P3、P4 之前决定）。
3. 新增依赖：CGAL 的 Python 绑定、整数规划求解器等，都尚未批准。

## 5. 其他待查事项

- 左右扳机的底模完全镜像，CoACD 却分出不同的块数，说明分解过程本身对输入敏感（可能是朝向、顶点顺序等）。验证方法：用同一个扳机底模和它的精确镜像，在相同参数下各分解一次。尚未执行。
- PhysX cooking 会再简化凸包（外壳单块从 1008 个顶点降到 49 个），这一步带来的误差还没有量化。
- 凸块之间的接缝会不会让接触法向抖动，阶段报告第 7.2 节的 H6 没有定论。
