# 数字按键的单点力与 T4 小球对照

**不能把 View/Menu/Guide 的 10/1 失败唯一归因于 T4 小球，也不能据此断言手指接触必须使用 64/16。** 本轮 P 的逐步原生施力已核实，4 ms 下这三个键在10/1及64/16均失败；原样T4在10/1失败、64/16通过。1 ms 下，P在10/1仍失败，在64/16全部通过；T4的1 ms时间重采样诊断在两组均通过。因此已确认加载通道、步长和迭代策略下的响应不同，**P的非物理静态响应的唯一内核原因仍未确认**。K由独立会话执行，本报告不替它作结论。

此前“0.4.1→0.4.2导致失败”的前提已被C1推翻，完整差异、对照和停止结论见 [view_attribution.md](view_attribution.md)。本轮仅使用0.4.2资源和a3。

## 裁定3：先核验施力

暂停首轮网格后，先做View专用逐步原生读回、同用例64/16、归一化核对，再从头运行带读回的完整P网格。初版没有发现导致结果失效的施力/评分错误；保留为“复核前数据”，未删除或改写成通过。最终正式表只取 `final-r1-iters-*` 四组。

### 实际力与作用点

公开SAPIEN接口没有暴露CPU外力累加器getter，因此实验目录中的只读C++适配器使用与a3相同的PhysX commit `5ca9f472105a90d70d957c243cb0ef36fe251a9f` 头文件，读取当前link的 `Sc::VelocityMod`：线加速度累加器×实际质量得到世界力，角加速度与世界惯量得到力矩；同时从原生API读取世界COM。没有修改SAPIEN、PhysX或共享环境。

View 10/1与64/16保持段的125步都读回 **2.390325307846 N**，沿正按压轴投影同样为正的2.390325307846 N。调用前、`scene.step()`后均为0，证明每步重新加入，既未漏加，也未逐帧累积。全部P正式组中，命令与原生力向量的最大误差 **1.388231e−6 N**；每组125/125或500/500个保持步均有正确幅值，调用前/步后最大值均0。

View的命令向量约为 `[-8.548e-7, -2.842e-7, -2.390325234] N`，与原生按压轴 `[-3.576279e-7, -1.189112e-7, -0.99999994]` 同向。实际碰撞三角面取点的link局部坐标为 `[-7.905858e-9, -3.911014e-9, 6.153680e-9] m`；中立世界点为 `[-.01134217110, .02382918987, .05088705812] m`，之后逐步随link变换。

原生累加器不保存“作用点”本身，不能虚构直接getter。逐步记录的作用点通过 `τ=(p−COM)×F` 与原生力矩交叉核对：View最大力矩误差 **1.175327e−9 N·m**。其余P也保存每步命令点、原生世界COM及力矩，原始记录可逐步复算。

力使用 `add_force_at_point(..., mode='force')`，每个ramp/hold步调用；没有把N误当N·s。SAPIEN实现直接转入PhysX `PxRigidBodyExt::addForceAtPos`。PhysX明确外力在仿真步后清零，须逐步重加：[PhysX 5.6.1 Applying Forces and Torques](https://nvidia-omniverse.github.io/PhysX/physx/5.6.1/docs/RigidBodyDynamics.html#applying-forces-and-torques)。

### 满行程力、上限和信号

View实际读回：K=**1239.517456 N/m**，D=**1.102146626 N·s/m**，target=**−18.999330 µm**，qf=**0 N**，限位 `[0, 1.266621985] mm`，drive mode=`force`，drive force_limit=**3.140000105 N**。于是：

`F_full = K*(q_upper-target)-qf = 1.593550156 N`

`F_P = min(16 N, 1.5*F_full) = 2.390325234 N`

这确实大于满行程弹性力。外加点力不受spring drive的force_limit直接裁剪；满程静态弹性需求也小于3.14 N。**没有读回求解器每个子步的drive冲量，故不能宣称瞬态drive从不饱和。** 弹簧参数及其cap与外力通道必须分开。

click的满程力使用实际−7.4 N持久qf，得到7.8 N，再乘1.5为11.7 N；没有误用仅Kq=.4 N。普通平移按钮约1.59355 N→2.390325 N；D-pad从实际作用点的有符号力臂，把满程弹性力矩换成N，约1.962494 N→2.943741 N。所有数值由实际模型读回，1.5倍/16 N为负责人指定诊断设置。

普通按钮信号算法为 `clip((q−lower)/(upper−lower),0,1)`，再应用已有neutral_epsilon；View读的是`back`，未改归一化/死区。专用力核验中：

### 这个平衡点能解释到什么程度

**普通静力平衡解释不成立，唯一数值机制尚未归因。** View 10/1在恒定q处，按弹性公式计算的反力只有1.059802 N；即使把原生qvel代入Dqvel（.024674 N），与2.390325 N外力及约.001962 N重力仍有约 **1.307811 N**差额。64/16原生qvel=0，弹性反力1.239158 N，仍有约 **1.153130 N**差额。无接触，q也未到上下限，不能编造壳体接触或静态弹簧力超过外力来配平。

精确源码显示TGS按位置子步计算隐式drive冲量，依赖速度、累计位移和已有冲量，再依次处理drive cap、位置限位和速度限位；末态qvel与位置子步累计运动存在不同缓存/写回路径。这给出“离散求解固定点”的机制候选，**没有子步drive/limit冲量trace或已验证的逐子步转录，不能把它写成已确认内核根因**。参见 [drive公式](https://github.com/NVIDIA-Omniverse/PhysX/blob/5ca9f472105a90d70d957c243cb0ef36fe251a9f/physx/source/lowleveldynamics/shared/DyCpuGpuArticulation.h#L75)、[原生drive/limit顺序](https://github.com/NVIDIA-Omniverse/PhysX/blob/5ca9f472105a90d70d957c243cb0ef36fe251a9f/physx/source/lowleveldynamics/src/DyFeatherstoneArticulation.cpp#L4589)。

一个已经执行并被推翻的候选是速度限位：先按URDF记录提出0.2 m/s限速可能截断外力响应；随后实际getter读回View为 **100 m/s**，仅在诊断进程将其改为PhysX浮点最大值后，10/1仍是.660032823。该单因素不能解释本例。没有把100 m/s或“取消限速”采用为生产配置。

若要进一步区分drive cap/限位冲量与TGS外力时间分配，最小后续验证需记录同一View每个位置子步的q、velocity、drive冲量、上下限和速度限位冲量，检验它们能否重建帧末固定点。此项**未执行**，本轮到此停止机制调查；不以合理猜测代替平衡解释。

## P/T4协议与环境

只在指定计算节点的独立 `-p` 镜像运行，CPU核8；CPU PhysX、TGS、cpu_workers=0，OMP/OpenBLAS/MKL=1，CUDA_VISIBLE_DEVICES和DISPLAY为空。已有a3/0.4.2环境，没有安装或覆盖共享包。16项为ABXY、View/Menu/Guide、LB/RB、D-pad四向、L3/R3、Pair；每项独立建场景，fixed root、原重力和SDF资源。

P：0.5 s无载settle、0.5 s线性力ramp、0.5 s全力hold、立即撤力后0.5 s observe。settle/ramp是我明确选择的诊断时序，用于避免把瞬时启动当保持失败；不能声称P具有T4的同一接近轨迹。对hold全部125或500个采样要求信号≥.95，撤力后按T4的持续中立判定，neutral_epsilon=1e−4；误触发定义复用T4。P没有创建外部接触体；本轮各P的contacts全部为空。模型关节、drive、信号默认值不写入。

P取实际碰撞triangle，不用凸包填平凹陷：对每键全部collision顶点AABB中心，沿反按压轴射线取最外侧真实三角交点，保存shape/triangle索引、重心坐标和link局部点。D-pad是一件rocker，四方向沿冻结8 mm有符号臂各取一个面上点，避免中心零力臂；施力点随link移动，力方向保持初始世界按压轴。Pair的P沿+native axis，原T4沿−axis；这两个用例方向不同，Pair结果不能直接互称修复。

4 ms T4：原样调用现有 `run_suite.run`、executor、runner与scorer，只把手柄迭代策略override为10/1或64/16；原球体半径4 mm、质量50 g、PD K3000 N/m、D12 N·s/m、上限16 N和其他冻结设置均保留。球体本身默认getter均10/1，`input_receipt.json`逐项保存手柄/球体读回；不能由球体getter推断接触求解组的有效迭代数。

1 ms T4：单独标为 `T4_dt1_diagnostic`，在实验脚本中按相同时间、轨迹/PD表达式和终止规则重采样，保持/观察各500步。未改冻结JSON、4 ms runner/scorer；因此它是诊断，不能冒充原样T4验收。P/T4返回时间以各自observe首采样为0，P从撤力起，T4从完成抬起后起，采样分辨率分别4/1 ms。
